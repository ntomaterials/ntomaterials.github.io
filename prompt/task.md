## 2. Цель и контекст проекта

Нужен онлайн-тест, который помогает школьнику выбрать профиль олимпиады НТО (Национальной технологической олимпиады, `P` профилей, количество профилей может меняться, на текущий момент `P = 29`). Методология подсчёта результата уже разработана и зафиксирована (раздел 4 ниже) — её нельзя менять, нужно только реализовать.

Пользовательский сценарий:

1. Школьник открывает тест по ссылке (в т.ч. со смартфона, в т.ч. встроенным на сайте олимпиады через iframe).
2. Отвечает на  вопросы по единой 5-балльной шкале.
3. Получает топ-3 рекомендованных профиля с процентом совпадения, кратким объяснением «почему подходит» и, если нужно, предупреждениями.

Ключевая архитектурная особенность: весь расчёт — детерминированная арифметика, которая целиком выполняется в браузере пользователя. Бэкенд, база данных и сетевые запросы во время прохождения теста не нужны.

## 4. Алгоритм расчёта результата (реализовать точно как описано, без изменений логики)

```
Шаг 1. Сбор ответов.
После прохождения теста система имеет массив из P числовых значений:
answers[q] ∈ {−2, −1, 0, +1, +2} для всех вопросов (q = А-01..А-24, Б-01..Б-05)

Шаг 2. Балл по каждому из кластеров блока А вычисляется как средний балл по двум вопросам:
raw_A[кластер] = average(все ответы по кластеру)   → диапазон [−2.0 .. +2.0]
u_norm[q] = (answer[q] + 2) / 4 × 3 = 3 × (answer[q] + 2) / 4   → нормализованное значение в диапазоне [0.0 .. 3.0]

Шаг 3. Балл по каждому из 5 типов деятельности блока Б
raw_B[тип] = answers[вопрос_Б]
score_B[тип] = (raw_B[тип] + 2) / 4                       → диапазон [0.0 .. 1.0]

Шаг 4. Предметный балл профиля S_A(p) — для каждого профилей p из P
числитель_A(p)   = Σ по всем кластерам: W_A[кластер][p] × score_A[кластер]
знаменатель_A(p) = Σ по всем кластерам: W_A[кластер][p], только где W_A[кластер][p] > 0
S_A(p) = числитель_A(p) / знаменатель_A(p);  если знаменатель_A(p) = 0 → S_A(p) = 0

Шаг 5. Деятельностный балл профиля S_B(p) — аналогично, по строкам блока Б
числитель_B(p)   = Σ по всем типам деятельности: W_B[тип][p] × score_B[тип]
знаменатель_B(p) = Σ по всем типам деятельности: W_B[тип][p], только где W_B[тип][p] > 0
S_B(p) = числитель_B(p) / знаменатель_B(p);  если знаменатель_B(p) = 0 → S_B(p) = 0

Шаг 6. Итоговый балл профиля
SCORE(p) = (4 × S_A(p) + 2 × S_B(p)) / 6      → диапазон [0.0 .. 1.0]
(вес предметной оси S_A — 4/6 ≈ 67%, вес деятельностной оси S_B — 2/6 ≈ 33%; веса не менять)

Шаг 7. Ранжирование
ranked = все 29 профилей, отсортированные по SCORE(p) по убыванию
top3 = ranked[:3]

Шаг 8. Проверки надёжности результата
gap = SCORE(top3[0]) − SCORE(top3[1])
  если gap < 0.10 → показать предупреждение:
  «Несколько профилей подходят тебе примерно одинаково — изучи каждый подробнее перед выбором»

max_score = SCORE(top3[0])
  если max_score < 0.45 → показать предупреждение:
  «Твои ответы не выявили ярко выраженных предпочтений. Попробуй ответить более определённо»
```


# Алгоритм расчёта рекомендуемого профиля НТО

### Шаг 1. Сбор ответов участника

Система получает 29 ответов и хранит их как массив:

```
answer[q] ∈ {−2, −1, 0, +1, +2}   для q = А-01..А-24, Б-01..Б-05
```

### Шаг 2. Нормализация ответов в диапазон [0; 3]

Каждый ответ приводится к той же шкале, что и веса профилей в матрице. Формула линейного масштабирования из [−2; +2] в [0; 3]:

```
u_norm[q] = 3 × (answer[q] + 2) / 4
```

Результаты по граничным значениям:

|answer[q]|u_norm[q]|
|---|---|
|+2|3.00|
|+1|2.25|
|0|1.50|
|−1|0.75|
|−2|0.00|

> **Почему прибавляем 2 и делим на 4?** Это стандартное min-max масштабирование: `(x − min) / (max − min)`. Для диапазона [−2; +2]: `(answer + 2) / 4` даёт [0; 1], умножение на 3 растягивает до [0; 3] — шкалы матрицы профилей.

### Шаг 3. Построение вектора пользователя

**Блок А — кластеры (12 компонент).** Для каждого кластера вычисляется среднее нормализованных ответов по двум вопросам этого кластера:

```
U_A[кластер] = (u_norm[вопрос_1] + u_norm[вопрос_2]) / 2

  → диапазон: [0.0 .. 3.0]
```

**Блок Б — типы деятельности (5 компонент).** Каждый тип — один вопрос:

```
U_B[тип] = u_norm[вопрос_Б]

  → диапазон: [0.0 .. 3.0]
```

**Итоговый вектор пользователя** — конкатенация обоих блоков:

```
U = [ U_A[ИТ-базовый],
      U_A[ИИ и данные],
      ...
      U_B[Программирование],
      U_B[Конструирование],
      U_B[Исследование],
      U_B[Анализ данных],
      U_B[Проектирование] ]

  Диапазон каждой компоненты: [0.0 .. 3.0]
```

> **Пример.** Участник ответил +2 и +1 на вопросы А-01, А-02 (кластер «ИТ-базовый»):
> 
> ```
> u_norm[А-01] = 3 × (2 + 2) / 4 = 3.00
> u_norm[А-02] = 3 × (1 + 2) / 4 = 2.25
> U_A[ИТ-базовый] = (3.00 + 2.25) / 2 = 2.625
> ```

### Шаг 4. Построение вектора профиля

Вектор каждого профиля `p` читается из матрицы весов напрямую — он уже находится в диапазоне [0; 3]:

```
P[p] = [ M[ИТ-базовый][p],
         M[ИИ и данные][p],
         M[Безопасность][p],
         M[Мобильные роботы][p],
         M[Сенсорика и встроенные системы][p],
         M[Физика и энергетика][p],
         M[Химия и материалы][p],
         M[Биология и медицина][p],
         M[Космос][p],
         M[Среда жизни][p],
         M[Пользовательские интерфейсы][p],
         M[Творчество и VR][p],
         M[Тип деятельности: Программирование][p],
         M[Тип деятельности: Конструирование][p],
         M[Тип деятельности: Исследование][p],
         M[Тип деятельности: Анализ данных][p],
         M[Тип деятельности: Проектирование][p] ]

  Размерность: 17
  Диапазон каждой компоненты: {0, 1, 2, 3}
```

После этого шага векторы `U` и `P[p]` живут в одном пространстве — расстояние между ними можно считать напрямую.

### Шаг 5. Вычисление весов компонент вектора профиля

Для взвешенного евклидова расстояния каждой компоненте назначается вес, пропорциональный её значению в векторе профиля:

```
w_i[p] = P_i[p] / Σⱼ P_j[p]
```

где суммирование в знаменателе идёт по всем 17 компонентам вектора профиля.

**Следствие:** компоненты с `P_i[p] = 0` дают `w_i[p] = 0` и не влияют на расстояние. Расхождение пользователя по теме, не связанной с профилем, не штрафует результат.

Если `Σ P_j[p] = 0` (профиль не имеет ни одного ненулевого веса — теоретически невозможно), то `D[p] = +∞` и профиль исключается из результатов.

### Шаг 6. Взвешенное евклидово расстояние

Для каждого профиля `p` вычисляется расстояние между вектором пользователя и вектором профиля:

```
D(U, p) = √( Σᵢ  w_i[p] · (U_i − P_i[p])² )
```

**Диапазон:** `D(U, p) ∈ [0.0 .. 3.0]`

- `D = 0` — идеальное совпадение по всем ненулевым компонентам профиля
- `D = 3` — максимальное расхождение: пользователь ответил «точно не моё» по теме, которая является ядром профиля

**Псевдокод:**

```python
for p in all_profiles:
    norm = sum(P[p])                      # знаменатель для весов

    sum_sq = 0.0
    for i in range(17):                   # по всем 17 компонентам
        if P[p][i] > 0:
            w_i = P[p][i] / norm          # вес компоненты
            diff = U[i] - P[p][i]         # расхождение
            sum_sq += w_i * diff * diff   # взвешенный квадрат

    D[p] = sqrt(sum_sq)
```

### Шаг 7. Ранжирование профилей

Все 29 профилей сортируются по **возрастанию** расстояния `D(U, p)`. Наименьшее расстояние = наибольшее сходство с профилем.

```python
ranked = sorted(all_profiles, key=lambda p: D[p])   # по возрастанию
top3   = ranked[:3]
```

Для отображения расстояние переводится в «процент совпадения»:

```
match_score[p] = round( (1 − D[p] / 3) × 100 )  %

  D = 0.0  →  100%  (идеальное совпадение)
  D = 1.5  →   50%  (среднее расхождение)
  D = 3.0  →    0%  (полная противоположность)
```


### Шаг 8. Проверки надёжности результата

**Проверка 1 — разрыв между 1-м и 2-м местом:**

```
gap = D[ranked[1]] − D[ranked[0]]

если gap ≥ 0.30  →  результат надёжен, показываем топ-3
если gap < 0.30  →  показываем предупреждение:
  «Несколько профилей подходят тебе примерно одинаково —
    изучи каждый подробнее перед выбором»
```

> Порог 0.30 соответствует ~10% от максимального расстояния (3.0).

**Проверка 2 — низкая вовлечённость:**

```
если match_score[ranked[0]] < 45  →  показываем сообщение:
  «Твои ответы не выявили ярко выраженных предпочтений.
    Попробуй ответить более определённо»
```

| Веса компонент                  | `w_i[p] = P_i[p] / Σ P_j[p]`                           |
| Диапазон D(U, p)                | [0.0 .. 3.0]                                           |
| Интерпретация D                 | 0 = идеальное совпадение, 3 = полная противоположность |
| Порог надёжности gap            | ≥ 0.30                                                 |
| Порог вовлечённости match_score | ≥ 45%                                                  |
| Число профилей в результате     | Топ-3 с наименьшим D                                   |

---

## 4. Адаптация решения 

Банк вопросов, список профилей и матрица весов могут быть изменены полностью.
Все данные по количеству вопросов, кластеров, активность, профилей, их веса берутся из приложенных csv файлов
При сборке теста анализируются эти файлы и собирается непосредственно код теста.
**Алгоритм расчёта не требует изменений кода.**
Важно: алгоритм расчета (шаг 5-6) должны быть выделены в отдельный модуль, который можно при необходимости заменить на другие функции расчета.

Формат вывода для каждого из топ-3 профилей:

| Элемент UI                      | Как считается                                                                                                                                                                                                                      |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Название профиля                | Полное название из `nto_profiles.csv` по коду                                                                                                                                                                                      |
| Балл совпадения                 | `round(SCORE(p) × 100)%`                                                                                                                                                                                                           |
| Почему подходит                 | Топ-2 кластера блока А с наибольшим вкладом `W_A[кластер][p] × score_A[кластер]`                                                                                                                                                   |
| Тип деятельности                | Тип деятельности с максимальным `W_B[тип][p]` (доминирующий для этого профиля)                                                                                                                                                     |
| Предупреждение (если применимо) | Кластер с `W_A[кластер][p] ≥ 2`, но `score_A[кластер]` участника `< 0.35` по этому кластеру → текст: «Этот профиль требует [кластер], но судя по твоим ответам, эта тема тебя пока не увлекает — изучи её подробнее перед выбором» |

## 5. Функциональные требования к интерфейсу

1. **Экран приветствия** — краткое описание теста, число вопросов, ориентировочное время прохождения, кнопка «Начать».
2. **Экран вопросов** — по одному вопросу на экран (или блоками), 5 вариантов ответа из раздела 3.4, индикатор прогресса (например, «12 из 29»), возможность вернуться к предыдущему вопросу и изменить ответ, запрет перехода дальше без ответа.
3. **Экран результата**:
    - топ-3 профиля карточками: название, балл совпадения, «почему подходит», тип деятельности, предупреждение (если есть);
    - блок предупреждений по шагу 8 (близкие баллы / низкая вовлечённость), если применимо;
    - возможность пройти тест заново.
4. Весь интерфейс — на русском языке, без потребности в регистрации или вводе личных данных.

## 6. Нефункциональные требования

- **Адаптивность**: корректное отображение и удобство использования на экранах от ~360px (смартфон) до широких десктопных мониторов, без горизонтальной прокрутки.
- **Производительность**: полная загрузка теста менее 2 секунд на среднем мобильном интернете; расчёт результата — мгновенный (без задержки, видимой пользователю).
- **Встраиваемость**: страница должна корректно работать внутри `<iframe>` на стороннем сайте (без ошибок CSP/X-Frame-Options на стороне самого теста).
- **Доступность (a11y)**: базовые требования — читаемый контраст текста, работоспособность с клавиатуры, понятные подписи для кнопок ответов.
- **Без сбора персональных данных**: ответы не должны отправляться на сервер и не должны сохраняться где-либо, кроме памяти текущей сессии в браузере (см. также раздел 8 «Вне скоупа» про опциональную статистику).

## 7. Технологический стек и архитектура (вариант A — статический сайт с автосборкой)

- Инструмент сборки: **Vite**. Фреймворк не обязателен — простой HTML/CSS/TypeScript (или JavaScript) без React/Vue, так как логика теста несложная; если предложишь framework (например, для удобства компонентов), обоснуй выбор коротко и держи бандл лёгким.
- Парсинг CSV на этапе сборки: **PapaParse** (или эквивалент), данные конвертируются в JSON и встраиваются в бандл при сборке — никаких `fetch()` к CSV в рантайме.
- Стили: чистый CSS или лёгкий CSS-фреймворк (по своему усмотрению), без тяжёлых UI-библиотек.
- Хостинг/деплой: статический хостинг с автосборкой из git-репозитория — **Netlify**, **Vercel** или **GitHub Pages** (выбери один, укажи конкретные шаги настройки). При пуше изменений в репозиторий (включая замену CSV-файлов) сайт должен пересобираться и публиковаться автоматически, без ручных действий.
- Репозиторий: Git (GitHub).

## 9. Валидация данных на этапе сборки

Сборка должна **падать с понятной ошибкой** (а не тихо показывать сломанный тест), если:

- в `nto_questions.csv` не ровно 29 строк / не хватает вопросов для какого-то кластера или типа деятельности;
- код профиля в столбцах матрицы не совпадает со списком кодов в `nto_profiles.csv` (или наоборот);
- значения весов в матрице выходят за диапазон 0–3;
- `group` вопроса не находит соответствия в строках матрицы.

Текст ошибки должен явно указывать, какой файл и какая строка/столбец не в порядке — чтобы методист, заменивший CSV с опечаткой, или разработчик могли быстро найти проблему.
